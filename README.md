# YUHADA HAIR — 정액권 관리 시스템

미용실 정액권(선불 잔액) 관리 웹앱.
관리자(태블릿)가 회원 등록/충전/차감하고, 고객(모바일)은 NFC 카드 태깅으로 잔액을 확인합니다.

## 스택

| 레이어 | 기술 |
|---|---|
| 서버 | Go + [chi](https://github.com/go-chi/chi) |
| 뷰 | [templ](https://templ.guide) + [HTMX](https://htmx.org) + [Alpine.js](https://alpinejs.dev) |
| 스타일 | Tailwind CSS v4 (standalone CLI), self-hosted 폰트 |
| DB | SQLite ([modernc](https://pkg.go.dev/modernc.org/sqlite), pure Go) + [sqlc](https://sqlc.dev) + [goose](https://github.com/pressly/goose) |
| 세션 | [scs](https://github.com/alexedwards/scs) / sqlite3store |
| SMS | [알리고](https://smartsms.aligo.in) LMS API |
| 배포 | Cafe24 VPS · systemd + nginx · GitHub Actions CD |

## 주요 기능

**관리자 (태블릿)**
- 허용된 카카오 계정 로그인
- 회원 등록/검색/삭제
- 잔액 충전/차감 (트랜잭션 보장)
- NFC 카드 발급/분실 신고/재활성화
- 대시보드 KPI (기간별 충전/차감 합계)
- 거래 내역 조회 (기간/타입/회원 필터)

**고객 (모바일)**
- NFC 카드 태깅 → 잔액 조회 (로그인 없음)
- 잔액 부족/분실 카드 안내 화면

**알림**
- 충전/차감 시 고객에게 LMS 자동 발송
- 최초 충전 시 이용약관 안내 포함

**보안**
- 회원 PII (이름/전화/메모) AES-256-GCM 암호화
- 전화번호: 결정적 암호화 (UNIQUE 제약 유지)
- 이름/메모: 랜덤 nonce (더 강한 보안)
- 카카오 이메일 화이트리스트, 인증 후 세션 회전
- debug 엔드포인트 프로덕션 자동 차단

## 기술 선택 이유

| 선택 | 이유 |
|---|---|
| **Go + SQLite** | 단일 바이너리 배포, VPS 1대로 충분한 소규모 매장. CGO 없이 크로스 컴파일 가능. |
| **templ + HTMX** | SPA 프레임워크 없이 서버 렌더링 + 부분 갱신. JS 번들 0KB. |
| **Alpine.js** | 모달/드로어 등 클라이언트 상태만 최소한으로. |
| **sqlc** | SQL을 직접 작성하되 타입 안전한 Go 코드 자동 생성. ORM 없이 투명한 쿼리. |
| **AES-256-GCM** | 고객 개인정보 DB 유출 시 평문 노출 방지. `enc:` 접두어로 하위호환 마이그레이션. |
| **SMS (알리고)** | 국내 문자 API. 핸들러에서 goroutine 비동기 발송, 실패해도 트랜잭션 무관. |

## 로컬 실행

```bash
make tools          # templ, sqlc, goose, tailwind CLI 설치
cp .env.example .env
make migrate-up     # DB 마이그레이션
make seed           # 빈 로컬 개발 DB에서만 예제 데이터 생성
make dev            # templ generate + CSS build + go run
```

`http://localhost:8080/login`은 `/v2/login`으로 이동합니다. 카카오 OAuth와 허용 이메일을 설정해야 관리자 로그인이 가능합니다. PIN 로그인은 제공하지 않습니다.

## v2 새 관리자 화면과 기존 원장

v2는 기존 운영 기능을 제공하는 새 관리자 화면입니다. v2 UI가 활성화되면 `/admin`과 모든 하위 주소는 대응하는 `/v2/admin` 주소로 이동하며 검색·기간 조건도 유지합니다. 구 화면의 HTMX 요청은 새 화면 전체를 열고, 구 주소의 일반 등록·충전·차감·삭제 요청은 409로 거부하여 거래를 자동 재전송하지 않습니다. 새 화면에서 다시 진행해야 합니다.

v2는 **같은 `DB_PATH`의 기존 `members`·`transactions`를 직접 사용**합니다. 회원·거래를 복사하거나 시험 자료를 운영 자료로 합치지 않습니다. 기존 고객 `/m/<카드 UUID>` 링크와 카드 UUID는 유지되며 새 화면에서 처리한 잔액을 그대로 보여줍니다. `V2_ENABLE=false`로 새 UI를 끄는 명시적 롤백 때만 기존 관리자 화면을 제공합니다.

| 항목 | 동작 |
|---|---|
| 진입 | `/v2/login` → `/v2/admin` |
| 운영 활성화 | `V2_ENABLE=true` + 신규 스키마 준비 + 새 바이너리 재시작 |
| DB | 기존 `DB_PATH` 사용. `DB_V2_PATH`는 폐기되어 새 운영 경로에서 무시 |
| 로그인 | `/login` → `/v2/login`, 카카오만 사용. 양쪽 POST 로그인/PIN 인증 제거 |
| 카카오 | 아래 이메일 화이트리스트로 관리자 허용 |
| 세션 | 서로 다른 쿠키·영속 저장소 유지. 승인된 카카오 로그인으로 양쪽 화면 인증, 어느 쪽 로그아웃도 모두 해제 |
| 문자 | 기존 알리고 설정과 메시지로 실제 발송. TEST/NoOp 환경이 아님 |
| 기존 화면 | `/admin`과 고객 `/m/...` 경로 유지 |

운영에서는 플래그 기본값이 `false`입니다. 신규 스키마가 준비되어 있으면 카카오 로그인 경로는 플래그와 무관하게 제공하며, `V2_ENABLE=false`일 때는 기존 `/admin`으로 로그인합니다. 개발 환경은 새 관리자 화면도 제공합니다. 신규 세션 표가 준비되지 않으면 관리자 로그인이 불가능하므로 먼저 일반 마이그레이션을 적용해야 합니다. 카카오 설정이 없을 때 PIN으로 우회할 수 없습니다.

### 스키마 적용과 전환

`migrations/00006_shared_ledger_memberships.sql`은 새 운영용 가격표·판매 이력·입력 프리셋·v2 세션 표와 그 기본값만 추가합니다. 기존 회원·거래를 수정·삭제·복사하지 않습니다. 과거 `v2_*` 시험 자료도 그대로 보존하며 새 화면은 이를 사용하지 않습니다. 앞선 조사에서 확인한 시험 회원 28명·거래 94건은 당시의 보존 기준이며, 운영 적용 전후에는 실제 값으로 다시 확인해야 합니다.

운영 전환은 일관된 DB 백업과 적용 전 기록을 확보한 뒤, 일반 `migrations/` 배포 절차로 신규 마이그레이션을 적용하고 바이너리·환경설정을 함께 검증합니다. **예전 시연에서 이미 `V2_ENABLE=true`였다면, 새 바이너리와 스키마 적용 후 `/v2`는 곧바로 실제 운영 화면이 됩니다.** 시험 화면으로 생각하고 충전·삭제 등을 실행하면 실제 원장에 반영됩니다.

운영에 `migrations-v2/`, `make migrate-v2-*`, 시험용 seed/reset을 실행하지 않습니다. 새 서버 기동 경로에도 과거 v2 마이그레이션·더미 회원 seed 자동 실행은 없습니다.

### 화면 동작과 매출 표시

일반 충전과 차감은 기존처럼 금액·메모·처리 후 잔액을 확인하고 한 번 제출합니다. 새 정액권 상품 판매에는 별도 확인 화면이 있습니다. 잔액이 부족하면 차감할 수 없습니다. 처리 성공 후 잔액과 이력을 함께 갱신하며, 통신 결과가 불확실하면 자동으로 다시 충전하지 않고 조회 화면으로 돌아갑니다. 브라우저 중복 클릭 방어가 서버 요청 재전송 전체의 멱등성을 보장하는 것은 아닙니다.

매출 화면의 **판매 금액**에는 과거 충전·최초 충전·일반 충전을 모두 원장 금액으로 포함합니다. 정액권 상품 판매는 구매 당시 기록한 판매가를 사용하고 보너스 적립액은 매출에서 제외합니다. 결제수단 기록이 없는 일반 충전은 판매 금액에 포함하되 결제수단은 **미상**으로 표시합니다.

### 화면 되돌리기

운영에서 `V2_ENABLE=false`로 변경해 재시작하면 새 관리자 화면만 중단하고 카카오 인증과 기존 `/admin`을 계속 사용할 수 있습니다. 이전 바이너리로 복귀할 때는 과거 PIN 로그인이 재활성화될 수 있으므로 인증 동작도 함께 확인해야 합니다. 기존 원장을 공유하므로 v2에서 이미 처리된 거래도 v1에 남습니다. **DB 삭제·복원 덮어쓰기나 마이그레이션 Down으로 되돌리지 않습니다.** 새 판매 이력과 기존 원장 자료를 보존합니다.

### 매장 현황과 PWA

매출 대시보드는 선택 기간의 판매 금액·시술 사용액·중복 없는 시술 고객·재충전 건수를 함께 보여줍니다. 첫 충전과 재충전은 전체 원장의 최초 충전 이력으로 구분하며, 차트는 긴 기간을 주별·월별로 묶어 과거 기록을 잘라내지 않습니다. 시술 사용액은 차감 거래만 포함하며 환불은 제외합니다.

현재 고객 잔액과 잔액 구간은 기간 필터와 별개인 현재 상태입니다. 재충전 안내 후보는 활성 회원 중 잔액 5만원 이하이면서 최근 60일 시술 차감 이력이 있는 고객입니다. 전체 후보 수와 최대 5명의 상세 링크를 구분해 표시하며 문자를 자동 발송하지 않습니다.

`/v2/admin/retention`의 **고객 재방문** 화면은 최근 6·12·24개월의 월별 재방문 고객 비중, 평균 방문 간격, 첫 기록 방문 월별 유지율과 현재 60·90·120일 미방문 고객을 제공합니다. 방문은 양수 시술 차감을 고객별 한국 시간 하루로 묶으며 충전·환불·미래 기록은 제외합니다. 월별 비중은 그달 방문 고객 중 이전 방문일이 있는 고객의 비율로, 같은 달의 앞선 방문도 포함합니다. 월초 이전 방문도 전체 원장에서 확인하며 과거 통계에는 비활성 회원도 포함합니다.

평균 간격은 선택 기간에 끝난 연속 방문 간격의 합을 간격 수로 나눕니다. 유지율은 첫 **기록** 방문 월의 고객 중 N개월 뒤 해당 달을 방문한 비율이며, 매달 연속 방문했다는 뜻은 아닙니다. 아직 마감되지 않은 달은 ‘관찰 중’, 미래 달과 분모가 없는 값은 ‘—’입니다. 기록 도입 전 방문이나 원장에 없는 시술은 알 수 없습니다. 장기 미방문 목록은 현재 활성 회원만 대상으로 마지막 방문 후 경과일을 계산하며 20명씩 전부 조회할 수 있습니다. 방문 기록이 없는 회원은 미방문 고객과 별도로 표시합니다. 이 화면은 조회만 수행하고 문자를 자동 발송하지 않습니다.

회원 상세의 **정액권·충전 이력**은 상품 판매뿐 아니라 최초·기존 충전도 최근 50건까지 함께 표시합니다. 과거 충전 금액만으로 상품·결제수단·보너스를 추정하거나 원장을 변경하지 않습니다.

회원·거래·카드·매출 상세 목록은 필터를 적용한 뒤 20건씩 페이지를 제공합니다. ‘더 보기’는 다음 페이지를 덧붙이고 전체 건수와 표시 범위를 갱신합니다. 새 필터는 첫 페이지부터 조회하며 일반 이전·다음 페이지 링크도 제공합니다. 거래 합계는 현재 페이지가 아닌 전체 검색 결과 기준이고, 거래 기간은 한국 시간 기준입니다. 암호화된 이름 검색에 필요한 전체 회원 조회는 500명 제한으로 잘라내지 않습니다.

정액권 충전은 확인 화면의 가격·적립·상품 정보가 제출 시점과 일치할 때만 처리합니다. 상품이 수정됐거나 이전 확인 정보가 없으면 창을 다시 열도록 안내하고 원장에 기록하지 않습니다. 최초 충전은 일반 금액 입력이므로 상품 선택은 회원 등록 후 충전에서 진행합니다. 저장·정렬·복사 실패를 성공으로 표시하지 않으며, 고객 잔액 화면의 최근 충전·방문은 최근 50건 제한과 별도로 전체 원장에서 조회합니다.

PWA manifest·192/512 앱 아이콘·maskable 아이콘·Apple 아이콘·파비콘을 제공합니다. 지원 브라우저에서 홈 화면에 추가할 수 있으며 시작 주소는 `/v2/login`입니다. 서비스워커는 공개 아이콘·스타일·폰트만 저장하고 회원·잔액·거래·API 응답은 저장하지 않습니다. 오프라인에서는 연결 안내만 표시하며 거래를 보관하거나 자동 재전송하지 않습니다.

## v2 카카오 관리자 이메일 화이트리스트

`/v2/login`에서 카카오로 로그인할 관리자는 서버 환경변수로 관리합니다.

```dotenv
KAKAO_REDIRECT_V2=https://yuhadahair.cafe24.com/v2/kakao/callback
ADMIN_KAKAO_EMAILS_V2=owner@example.com,manager@example.com
```

카카오디벨로퍼스에서 같은 REST API 키의 리다이렉트 URI를 등록하고,
**카카오 로그인 → 동의항목 → 카카오계정(이메일)** 사용 설정을 켜야 합니다.
`KAKAO_CLIENT_ID`는 REST API 키이며, Client Secret이 활성화되어 있으면
`KAKAO_CLIENT_SECRET`도 설정합니다. 환경변수를 변경한 뒤에는 서비스를 재시작합니다.

이메일 목록을 설정하면 카카오 인증 시 `account_email` 동의를 요청하며,
카카오가 유효하고 인증된 것으로 확인한 대표 이메일만 목록과 비교합니다.
주소 앞뒤 공백과 대소문자는 무시하지만, 별칭·부분 문자열·도메인 단위로는 허용하지 않습니다.
이메일 미제공, 미동의, 미인증, 유효하지 않은 이메일, 미등록 주소는 로그인할 수 없습니다.
이메일은 DB나 세션에 저장하지 않습니다.

이메일 목록이 설정된 환경에서는 `ADMIN_KAKAO_ID_V2`로 우회할 수 없습니다.
이메일 목록이 비어 있을 때만 기존 ID 화이트리스트를 사용하며,
두 설정 모두 없으면 관리자 권한을 부여하지 않습니다. PIN 로그인과 PIN 부트스트랩은 제거했습니다. 기존 PIN으로만 인증된 세션은 관리자 권한으로 인정하지 않아 카카오 재로그인이 필요합니다. 과거 관리자 DB 기록은 보존하며 `ADMIN_PIN_V2`와 `ADMIN_BOOTSTRAP_PIN` 등의 예전 환경변수는 읽지 않습니다.

공식 응답 필드: [카카오 사용자 정보 조회](https://developers.kakao.com/docs/ko/kakaologin/rest-api#req-user-info).

## 배포

`main` 브랜치 push 시 GitHub Actions가 자동 배포:

1. templ generate + Tailwind CSS build
2. Linux amd64 크로스 컴파일 (`CGO_ENABLED=0`)
3. 바이너리 + static + migrations를 VPS에 업로드
4. goose 마이그레이션 실행
5. systemd 서비스 재시작

## 주요 명령

```bash
make dev            # 개발 모드
make build          # Linux amd64 크로스 컴파일
make css-watch      # Tailwind watch
make templ-watch    # templ watch
make migrate-up     # 마이그레이션 적용
make test           # 테스트
```
